## Setup

Tools built from source with Go 1.27.1 into a scratch folder outside the repository: sqldef 3.11.30 (`sqlite3def`, `psqldef`; MIT licence) and pgschema 1.14.1 (Apache 2.0). Engines: SQLite (file database, in process) and PostgreSQL 17.7 (the `oobd-test-postgres` stack container, throwaway databases). Fixture: 20 tables with primary, foreign and unique keys, defaults and unique indexes, plus one view (generated by script, plain `CREATE` statements; no function, trigger or extension yet).

## Findings

- sqldef is safer by default: every drop is skipped unless `--enable-drop`. Its plan is plain SQL text, so a wrapper reads exit codes and parses nothing richer.
- pgschema has the better plan format (JSON, saved plan applied later, lock timeout), but plans drops without a gate; a wrapper must refuse a plan with drop steps itself.
- Neither tool reports the hazard of a type narrowing or a rewrite (S6).
- pgschema needs a second database for planning (`--plan-host`) when the embedded Postgres is not used.
- Licences: sqldef MIT (the parser directory has its own licence, not checked), pgschema Apache 2.0. Both fit REQ-008.

## Decision per engine

Provisional, to be confirmed by the owner:

- **PostgreSQL:** buy with gaps. Wrap sqldef for the safe default or pgschema for the JSON plan; either way layer 2 adds a drop gate and a narrowing/rewrite check on the plan.
- **SQLite:** buy with gaps (sqldef); renames and type changes need a custom step.
- **SQL Server:** DacFx stays the baseline; `mssqldef` passes S1 to S3 and S5 but emitted an invalid `ALTER COLUMN` with a default for S6, so it is not a replacement.
- **Oracle:** unchanged (Q5).
