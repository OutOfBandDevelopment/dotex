## Docs check for imported material (2026-11-03)

`OoBDev.Docs.Tests` now fails when a markdown file under `docs/applications/{app}/` is orphaned.

### Done

- `ImportedDocsCoverage.FindOrphans` treats a file as covered when the application readme reaches it through links (a link to a folder covers everything below it) or when a document in `docs/migration` names the file or one of its folders. An application folder without a `README.md` is reported.
- `Applications_ImportedDocuments_AreLinkedOrMapped` runs it for every application folder; `ImportedDocsCoverageTests` covers the rules (linked, folder-linked, mapped, orphan, no readme) against a throwaway tree.
- The default scope widens to `docs/patterns-discovery;docs/applications` (`DocsTests`, `src/.runsettings`, `TEST_VARIABLES.md`, the style guide and `CLAUDE.md`).
- First run found 21 `docs/applications/devterm/changes` files that nothing linked; the devterm readme now links the `devices`, `bugs`, `changes` and `source` folders (and no longer names a `scratchpad` folder that does not exist).

### Verified

`dotnet test src/Tools/OoBDev.Docs.Tests --filter "TestCategory=Unit"`: 8 passed, 0 failed. The PlantUML render test (Integration) was not run.

## Drawing on SkiaSharp (2026-11-03)

Closes the "Drawing cross-platform" backlog item (owner, 2026-10-29: Windows only for now, SkiaSharp later) and Table 4 row 3 of the [BinaryDataDecoders re-review](../migration/binarydatadecoders-rereview-2026-10-29.md).

### Done

- `Code39`, `MultiScaleTile` and `PngPack` use `SKBitmap`, `SKCanvas` and `SKImage` instead of `System.Drawing.Common` (`Image`, `Bitmap`, `Graphics`); `[SupportedOSPlatform("windows")]` is gone and the library has no `System.Drawing.Common` reference. `SkiaSharp` and `SkiaSharp.NativeAssets.Linux.NoDependencies` come from `Directory.Packages.props`.
- `System.Drawing.Size` and `Point` stay (BCL primitives), so `SizeExtensions` is unchanged; `ZOrderCurve` and `JpegSegmentReader` were already platform-free.
- Behaviour kept: Code 39 bitmaps are 16 pixels per symbol and 16 high (now `Gray8`, bit 1 white), tiles are JPEG quality 75, `PngPack` keeps the 4-byte length header and BGRA pixel layout (unpremultiplied, so every byte round-trips).
- New behaviour: path and stream overloads throw `InvalidDataException` for data that is not an image; stream overloads leave the caller's stream open.

### Verified

`dotnet test src/Extensions/OoBDev.Extensions.Drawing.Tests`: 55 passed, 0 skipped (the Windows-only `Assert.Inconclusive` guards are removed). Run on Windows only; the Linux native asset is referenced but a Linux run was not performed here.

## Shared FakeTransport (2026-11-03)

Closes the last candidate in the [test-utilities plan](../design/DevTermParity/test-utilities-plan.md).

### Done

- `OoBDev.DevTerm.TestUtilities/FakeTransport.cs` is the one in-memory `IDeviceAdapter` and `ILineStatusSource` for tests. It is the superset of the four copies: records writes (`WrittenPayloads`, `WrittenText`), answers each write (`ReplyToEveryWrite`), fails every write (`FailWritesWith`), the next write or open (`FailNextWrite`, `FailNextOpen`), hangs up or fails the read side, and reopens with a fresh pipe after a close.
- The copies in `Core.Tests` (Logging, DeviceManifests), `Devices.Tests` and `Tui.Tests` are deleted. `Devices.Tests` references the project and has the global using.
- State changes raise `StateChanged` only when the state really changes (the Logging and Tui behaviour; the other copies raised it on every set).

### Verified

`dotnet test`: `Core.Tests` 1065 passed (8 skipped), `Devices.Tests` 77 passed, `Tui.Tests` 385 passed (8 skipped); no failures. `Tui.Tests` rewrote the generated guide screenshots, which were reverted (nondeterminism is tracked in `BACKLOG.md`).
