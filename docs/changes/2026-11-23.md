## DevTerm: out-of-process transport plugins

A `process` plugin with `"kind": "transport"` is a device transport run as a child process (`ExternalProcessAdapter`, JSON lines with hex payloads: `open`/`write`/`close` out, `opened`/`data`/`error`/`closed` back). It registers as a `PluginTransport` after approval and `--transport {name}` selects it; presenter-only paths ignore transports. Silence, exit or a bad line faults the adapter. Example in `examples/devterm/powershell/out-of-process-transport/`. Verified live with `pwsh` echo devices: `ExternalProcessAdapterTests` and the loader test in `PluginTrustProcessTests` pass (14 passed, 1 skipped for the missing Python). Device-module plugins remain open. Design: [out-of-process plugins](../design/Plugins/out-of-process-plugins.md).

## Complex events: ScheduleAt, cron recurrence and catch-up policy

`IRecurrence`, `CatchUpPolicy` (`Skip`, `RunLatest`, `RunAll`) and `ScheduleAtAttribute` (UTC cron default per event type, overridable by configuration) are in `OoBDev.ComplexEvents.Abstractions`. `CronRecurrence` is a built-in five-field parser (lists, ranges, steps, Vixie day-of-month/weekday rule) so no third-party cron package is needed. `RecurringSchedule.EnsureAsync(lastRun)` registers missed occurrences per the policy plus the next one, each as its own key so repeats never duplicate. Tests in `RecurrenceTests` (26 Unit tests pass in the project). Not built: persisting the last run time in the hosted service, Event Hubs, dead-letter publish.

## Data loader: batched writes

`IBatchRowSink.WriteBatchAsync` and `LoadOptions.BatchSize` (default 1, row by row): the loader buffers accepted rows and flushes per batch. `EfRowSink` implements it with one context, one key lookup and one `SaveChanges` per batch, applying the duplicate policy to stored keys and to repeats inside the batch. Tests: a batched CSV load and a replace-with-repeat batch (Simulate, SQLite, 5 pass). Not wrapped in a transaction across batches.
