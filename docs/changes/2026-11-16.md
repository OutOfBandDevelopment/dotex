## Database work queue, first slice

- New Framework project `OoBDev.WorkQueue` (no database reference): `IWorkQueue` (enqueue, claim, heartbeat, complete, fail, redrive, stats, dead letters), `StageSla` and `WorkQueueOptions` with per-stage overrides and exponential back-off, `InMemoryWorkQueue` (same lease, fence and back-off rules; the unit-test provider), and `StageWorker` hosted services added with `AddWorkStage<THandler>(stage)` and enabled by stage name in configuration.
- New adapter `OoBDev.PostgreSql.WorkQueue` (grouped with the pgmq adapter under `ExternalServices/PostgreSql`): claim with `FOR UPDATE SKIP LOCKED` after a sweep of exhausted items into dead letters (parked if hung, dead if failing), fenced heartbeat, complete and fail, redrive, stats, a generated idempotent schema script (`MigrateAsync`) with validated schema and table names, and a pluggable `IPostgresClaimOrder` (default oldest first).
- Tests: `OoBDev.WorkQueue.Tests` 30 Unit tests passed; `OoBDev.PostgreSql.WorkQueue.Tests` 18 passed (9 Unit, 9 Integration against the running `pgvector` container, one throwaway schema per test). Coverage was collected but the percentage was not read out, so the 85 to 90 percent target is not confirmed.
- Not built: worker events and history retention, the PGMQ reader, application stages. The design moved the adapter to `ExternalServices/PostgreSql/OoBDev.PostgreSql.WorkQueue` (was `OoBDev.WorkQueue.Postgres`).
