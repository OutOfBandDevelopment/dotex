## Vectors database redeploy is idempotent (2026-10-29)

Deploying the same `OoBDev.Data.Vectors.DB` dacpac over a populated database used to drop and recreate the four CLR user-defined types (Matrix, MatrixF, Vector, VectorF), the aggregates and the functions, then rebuild `embedding.HashPlanes` and `embedding.Vectors`. The rebuild failed with Msg 4936 (the persisted computed column `Length` "cannot be persisted because the column is non-deterministic"), because the types it depends on had just been dropped.

Two causes, both fixed:

- **UDT elements.** `DacPacBuilder.UserDefinedTypes` wrote `Format`, `MaxByteSize`, `IsByteOrdered` and a `Methods` relationship into each `SqlUserDefinedType`. The model DacFx builds from the deployed database carries only the class name, assembly and schema, so every type compared as changed. These values already live in the assembly's `SqlUserDefinedType` attribute and SQL Server reads them from there on `CREATE TYPE ... EXTERNAL NAME`, so the builder no longer emits them (`Methods(...)` stays available as a public method, unused by the type element).
- **Computed columns.** The persisted `Length` and `Magnitude` columns of both tables are written as `CONVERT([embedding].[VectorF],[Value]).Length()`, the form the database reports back, so they no longer compare as a different expression.

Test: `SqlServerDeploymentTests.Redeploy_SameDacpac_ChangesNothing` (Integration, Docker SQL Server) generates the deploy script for a second deployment and asserts it neither drops a type nor rebuilds a table, then deploys with `BlockOnPossibleDataLoss`. It failed with Msg 4936 before the change. All 8 tests of `OoBDev.Data.Vectors.DB.Tests` pass. The dacpac was rebuilt in Debug and Release.

## SCPI definite-length block replies (2026-10-29)

`ScpiReplySegmenter` now cuts an IEEE 488.2 definite-length block (`#<n><length>` followed by that many bytes, for example a screen dump) as one segment, so CR, LF or `#` bytes inside the data no longer split it. `ScpiMessageDecoder` returns the data without its prefix in the new `ScpiReply.Block`; text replies are unchanged (`Block` is empty).

A `#` that is not followed by a digit 1 to 9 and the right number of digits stays an ordinary line. A block that is shorter than its declared length waits for more bytes. Indefinite blocks (`#0`) and block reassembly for profiles with an empty terminator are not supported; both are noted in `README.Scpi.md`.

Tests (Unit, 35 pass in `OoBDev.Scpi.Tests`): a block with CR/LF/`#` inside, split across two arrivals and followed by a text line; four non-block `#` lines; a truncated block decoded as text. Not run against a real instrument.

## SCPI reply tracker and auto-detect (2026-10-29)

`ScpiReplyTracker` pairs queries with replies. `QueryAsync(request)` queues the request through a `send` delegate (for example the stream device's `Transmit`) and waits for the oldest open slot's reply; the consumer feeds decoded replies to `OnReply`. A query that times out or is cancelled keeps its place and discards its late reply, so later answers stay in step; a reply with nothing open raises `Unsolicited`. `SendAsync` is for commands without a reply. `ScpiAutoDetect.IdentifyAsync(tracker, catalog, terminator)` sends `*IDN?`, matches the reply with `TryMatchByIdn` and falls back to `ScpiProfileCatalog.Generic`.

The tracker is a separate type, not part of `ScpiDevice`, because SCPI sends `ScpiRequest` and receives `ScpiReply`, which a single `IStreamDevice<T>` cannot carry. Wire it with a transmit-only and a receive-only device, or a pair that share the port.

Tests (Unit, 11 added, 46 pass in `OoBDev.Scpi.Tests`): reply, two queries in order, timeout then late reply, cancel, refused send, non-query, unsolicited reply, command send, null argument, known and unknown `*IDN?`. Not done: the generated control panel (DevTerm merge) and a real instrument.

## Z-Wave ACK responder (2026-10-29)

`ZWaveAckResponder.Respond(frame)` picks the one-byte answer the Serial API wants for each received unit: `ZWaveFrame.Ack` for a checksum-valid data frame, the new `ZWaveFrame.Nak` for a frame that starts with `0x01` but fails its checksum, and `null` for lone ACK, NAK and CAN bytes and stray bytes. ## Z-Wave session (2026-10-29)

`ZWaveSession` wraps the framework's `IStreamDevice<ZWaveFrame>` (the existing `StreamDevice<T>` over a device adapter is the production one, so no new session observer was needed). It subscribes to `MessageReceived`, queues the answer `ZWaveAckResponder.Respond` picks, applies the frame to its `ZWaveNodeTable` and raises `FrameReceived`; `SendAsync(frame)` queues a request. `AnswerFailed` reports an answer the device refused or could not send. `Dispose` unsubscribes.

Build the stream device with `minimumTransmissionDelay: 0`: the default of 1000 ms is a gap after every transmission, so an acknowledgement could wait behind it close to the stick's timeout. The session cannot change that, so the type documentation says so.

Tests (Unit, 8 added, 50 pass in `OoBDev.ZWave.Tests`) use a fake `IStreamDevice<ZWaveFrame>`: data frame acknowledged and relayed, lone ACK relayed without an answer, refused answer, a throwing transmit, `SendAsync`, `Dispose`, null arguments. Not run: a Hardware pass with a real stick through `StreamDevice<T>`, and the `ZWaveStick` test helper now runs through `ZWaveSession` over a `StreamDevice<ZWaveFrame>` on `SerialPortDeviceAdapter` (2026-10-29; the real-stick Hardware tests pass 50 of 50, twice; Dispose waits 500 ms so the last ACK leaves the queue, otherwise the stick retransmits into the next test).

## SQL Server Service Broker queue provider

**Date:** 2026-10-29

New adapter `OoBDev.Microsoft.SqlServer.ServiceBroker` (ExternalServices/Microsoft, with `.Tests`): `ServiceBrokerQueueMessageProvider` implements `IMessageSenderProvider` and `IMessageReceiverProvider` under the key `sql-service-broker`, with `TryAddServiceBrokerServices()`, an AsyncAPI contributor (host and queue only, never the connection string) and optional idempotent creation of the message type, contract, queue and services (`EnsureObjects`).
