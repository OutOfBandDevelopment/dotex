# Changes 2026-11-19

## Harness test for the lease-before-inspect order

- `IntegrationContainersTests.Ensure_TakesTheLeaseBeforeLookingAtTheContainerAsync`: the process lease file exists before the first Docker inspect, so a process finishing its tests cannot stop a container this one is about to use. `OoBDev.TestUtilities.Tests` 14 passed.

## Refreshable option lists for form choice rows

- `ChoiceControl.OptionsSource` keeps the `[FormField(OptionsFrom)]` property name; `FormBinding.GetOptions` reads it; `ChoiceViewModel` re-reads it on every refresh and replaces its options and `OptionItems` (now an observable collection), so a list that changes while the form is open (detected serial ports) updates. A fixed list is unchanged. First prerequisite for putting the WPF Connection Editor on the generated form (the other two, object-valued picks and scan command properties, stay in the [spec](../applications/devterm/specs/connection-editor.md) and `BACKLOG.md`). `OoBDev.UiDefinitions.ViewModels.Tests` 68, `OoBDev.UiDefinitions.Tests` 197 and `OoBDev.UiDefinitions.Wpf.Tests` 14 passed (generator test extended, four new tests).
- Also: the per-test timing of the Integration run is recorded in `BACKLOG.md` (container start-up and the CPU embedding tests dominate, not the test bodies).

## Object-valued choice rows

- A choice row whose property holds an object (the detected LXI, BLE, HID and USBTMC devices of the Connection Editor) shows each source item by its `Display` text (`FormBinding.Format` reads a string `Display` property) and writes the picked item itself into the model (`SetText` finds it in the `OptionsSource` list). ## Integration warm-up script

- `scripts/ci/warm-up-integration.ps1` pulls and starts the slow integration services (pgvector, SQL Server, Ollama, SBERT, Keycloak, OpenSearch, Neo4j; not the Service Bus emulator, which must start after a fresh SQL Server) detached before the build, aimed at the 1 to 2.5 minute container waits of the first test per project. Verified with `-DryRun` (names checked against the compose file, unknown name rejected); measured: the full `OoBDev.slnx` Integration run (stack down, build included) took 5 min 3 s with the warm-up against about 7 min 50 s before, 42 of 46 projects green in that run; the four failures were Docling and the Stomp test under load (both pass alone) and the Service Bus emulator, which failed because it starts against the SQL Server volume of an earlier emulator run (`Cannot create file SbGatewayDatabase.mdf`), so it was dropped from the warm-up and after `docker volume rm oobd-test-sqlserver-data` its tests pass. See [suite-timing.md](../architecture/testing/integration/suite-timing.md#warm-up-script-2026-11-19).
