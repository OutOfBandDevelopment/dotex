## CQRS design: three separate providers

At the owner's request the event store, the event stream (message queue) and the entity store are separate providers, each selected by its own configured key and swappable by deployment. The design adds `IEventStream`, `IEntityStore` and an `EventRelay` (store position to stream, so there is no dual write), folds the checkpoint store into the entity store, and updates the figure, the registration example and the decisions. No code is written yet.

## CQRS design: Entity Framework stores

At the owner's request the event store and the entity store get an Entity Framework Core implementation with PostgreSQL, SQL Server and SQLite as configurable databases. The design adds the table layout, the config keys, per-database provider projects with their own migrations, the identity-gap handling for the global feed and a shared contract test run on every database. A PostgreSQL service for the test stack and the project-home question (Q1) are recorded; no code is written yet.

## CQRS design: existing queue pattern, CloudEvents at the edge

At the owner's request the event stream uses the existing message-queue pattern (`IMessageQueueSender`, `IMessageQueueHandler`, `IMessageContext`) with no new stream contract, and CloudEvents is an edge mapper over it instead of the internal envelope. The internal shape is a plain `EventRecord`. The first queues are Azure Service Bus and Storage Queues and SQL Server Service Broker (all exist) plus a new PostgreSQL pgmq adapter, which is on the backlog with the PostgreSQL test service. No code is written yet.

Layout confirmed by the owner: the Entity Framework stores and model are in `OoBDev.EventSourcing.EntityFrameworkCore` with one small project per database (`.Postgres`, `.SqlServer`, `.Sqlite`), all in Framework. The question is removed from `OPEN-QUESTIONS.md`.

## CQRS design: dacpac for SQL Server

Schema delivery is split by database at the owner's request: EF Core migrations for PostgreSQL and SQLite, and a SQL project that builds a dacpac (like `OoBDev.Example.DB`) for SQL Server, deployed with DacFx. A parity test compares the EF model with the deployed dacpac. The SQL project sits in Framework beside the EF projects (my assumption, same layering as the confirmed layout). No code is written yet.
