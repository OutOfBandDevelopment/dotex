## CQRS library: abstractions, in-memory stores and event relay

First build step of the event sourcing library. `OoBDev.EventSourcing.Abstractions` holds `IEventStore` (append with expected sequence, conflict reported as a result, read by stream, read by global position), `IEntityStore` (versioned entities, prefix query), the records and the `EventsChannel` marker. `OoBDev.EventSourcing` holds thread-safe in-memory stores, `EventRelay` (reads by position after a checkpoint kept in the entity store, sends through `IMessageQueueSender<EventsChannel>` with message id stream:sequence, honours a safety window and batch size, fails when another instance took its checkpoint), and `TryAddEventSourcing()` with the stores chosen by `OoBDev:EventSourcing:EventStore:Type` and `EntityStore:Type` (unknown key throws). 17 Unit tests pass (`dotnet test src/Framework/OoBDev.EventSourcing.Tests`); the coding-standards checks pass. Coverage was not measured. Not built yet: EF stores, the dacpac project, the CloudEvents mapper, a hosted relay loop, aggregates and projections.

## CQRS library: Entity Framework Core stores

## CQRS library: CloudEvents edge mapper

`CloudEventMapper` in `OoBDev.EventSourcing` converts an `EventRecord` to and from a CloudEvents 1.0 structured JSON document (`id` = `{StreamId}:{Sequence}`, `subject` = stream id, `sequence` and `metadata` extension attributes); external events with only an `id` of the form `stream:sequence` are accepted and invalid documents raise `FormatException`. Four Unit tests (round trip, required attributes, external event, invalid inputs) pass with the other 25 in `OoBDev.EventSourcing.Tests`. It is not yet wired to an HTTP endpoint or a queue adapter option.

## pgmq message-queue adapter

`OoBDev.PostgreSql.Pgmq` (ExternalServices) plugs PostgreSQL pgmq queues into the existing message-queue pattern under the provider key `pgmq` (`TryAddPgmqQueueServices`). Sending calls `pgmq.send`; receiving calls `pgmq.read` with a visibility timeout and archives a message after its handler succeeds, so a failing handler gets the message again (at-least-once). Settings: `ConnectionString`, `QueueName`, `VisibilityTimeoutSeconds`, `PollIntervalMilliseconds`, `BatchSize`. `Npgsql` is now a central package version. Tests: 5 Unit (settings defaults and overrides, missing keys, registration) and 3 Integration against the test PostgreSQL container (send, deliver and archive, redeliver after a failed handler); all 8 pass. Not built: AsyncAPI contributor and dead-lettering (BACKLOG).

## CQRS library: aggregates and repository

`AggregateRoot` and `IAggregateRepository<T>` (Abstractions), `AggregateRepository<T>`, `EventTypeRegistry` and `[EventType]` (OoBDev.EventSourcing). An aggregate raises events, the repository stores them as JSON in the stream `{TypeName}-{id}` with the aggregate's version as the expected sequence (a lost race throws `EventStreamConflictException`) and rebuilds by replay. Resolved through `TryAddEventSourcing()` using the selected event store. 7 new Unit tests (save and load, null for unknown, event names, concurrency conflict, no-change save, duplicate name, DI); 32 tests in the project pass. Not built: snapshots, upcasting.
