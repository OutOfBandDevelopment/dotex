## CQRS library: abstractions, in-memory stores and event relay

First build step of the event sourcing library. `OoBDev.EventSourcing.Abstractions` holds `IEventStore` (append with expected sequence, conflict reported as a result, read by stream, read by global position), `IEntityStore` (versioned entities, prefix query), the records and the `EventsChannel` marker. `OoBDev.EventSourcing` holds thread-safe in-memory stores, `EventRelay` (reads by position after a checkpoint kept in the entity store, sends through `IMessageQueueSender<EventsChannel>` with message id stream:sequence, honours a safety window and batch size, fails when another instance took its checkpoint), and `TryAddEventSourcing()` with the stores chosen by `OoBDev:EventSourcing:EventStore:Type` and `EntityStore:Type` (unknown key throws). 17 Unit tests pass (`dotnet test src/Framework/OoBDev.EventSourcing.Tests`); the coding-standards checks pass. Coverage was not measured. Not built yet: EF stores, the dacpac project, the CloudEvents mapper, a hosted relay loop, aggregates and projections.

## CQRS library: CloudEvents edge mapper

## pgmq message-queue adapter

`OoBDev.PostgreSql.Pgmq` (ExternalServices) plugs PostgreSQL pgmq queues into the existing message-queue pattern under the provider key `pgmq` (`TryAddPgmqQueueServices`). Sending calls `pgmq.send`; receiving calls `pgmq.read` with a visibility timeout and archives a message after its handler succeeds, so a failing handler gets the message again (at-least-once). Settings: `ConnectionString`, `QueueName`, `VisibilityTimeoutSeconds`, `PollIntervalMilliseconds`, `BatchSize`. `Npgsql` is now a central package version. Tests: 5 Unit (settings defaults and overrides, missing keys, registration) and 3 Integration against the test PostgreSQL container (send, deliver and archive, redeliver after a failed handler); all 8 pass. Not built: AsyncAPI contributor and dead-lettering (BACKLOG).

## CQRS library: aggregates and repository

`AggregateRoot` and `IAggregateRepository<T>` (Abstractions), `AggregateRepository<T>`, `EventTypeRegistry` and `[EventType]` (OoBDev.EventSourcing). An aggregate raises events, the repository stores them as JSON in the stream `{TypeName}-{id}` with the aggregate's version as the expected sequence (a lost race throws `EventStreamConflictException`) and rebuilds by replay. Resolved through `TryAddEventSourcing()` using the selected event store. 7 new Unit tests (save and load, null for unknown, event names, concurrency conflict, no-change save, duplicate name, DI); 32 tests in the project pass. Not built: snapshots, upcasting.

## CQRS library: hosted relay loop

New project `OoBDev.EventSourcing.Hosting` (the same split as `OoBDev.MessageQueueing.Hosting`) with `EventRelayHost`, a `BackgroundService` that runs `EventRelay.RunOnceAsync` back to back while events wait and pauses `PollInterval` (new relay option, default 1 s) when idle; a failing pass is logged and retried. `TryAddEventRelayHost()` registers it. 2 Unit tests (sends stored events then stops; keeps running after a sender failure); 34 tests in the project pass.

## CQRS library: projections

`IProjection` (Abstractions) and `ProjectionRunner` (OoBDev.EventSourcing): catch-up reads the event store by global position from each projection checkpoint (entity type `projection-checkpoint`), applies in batches, saves the checkpoint per batch (a lost race throws), and `ResetAsync` clears a checkpoint to rebuild. Registered by `TryAddEventSourcing()`. 4 Unit tests (batches, only new events, separate checkpoints, reset); 38 tests in the project pass. Not built: a queue-fed projection host (a handler on `EventsChannel` works with the existing pattern).

## CQRS library: event upcasting

`IEventUpcaster` (Abstractions) and `EventUpcastPipeline` chain old event shapes to the current one at read time with cycle detection; `AggregateRepository` applies the pipeline on load (optional constructor parameter, registered by `TryAddEventSourcing()`). 3 Unit tests; 41 tests in the project pass. Not wired into projections (a projection can call the pipeline itself).

## CQRS library: aggregate snapshots

`ISnapshotable`, `SnapshotOptions` (`OoBDev:EventSourcing:Snapshots:Interval`, default 100) and snapshot support in `AggregateRepository`: after a save that passes an interval multiple the state goes to the entity store (`aggregate-snapshot`), and a load restores it and reads only the later events. `AggregateRoot.LoadFromSnapshot` sets identity and version. 3 Unit tests (stored at interval, tail-only replay, interval 0 off); 44 tests in the project pass. Snapshots are not upcast; changing a state shape means deleting the snapshots.

## pgmq adapter: dead-lettering

New setting `MaxDeliveries` (default 5, 0 off). The receive loop reads `read_ct` from `pgmq.read`; a message read more often than the limit is sent to `{QueueName}_dlq` (created with the queue) and archived instead of being handled again. The archive call is no longer cancellable, so a message the handler finished is archived even while the host stops (this fixed a race in `RunAsync_DeliversToHandlerAndArchives`). New Integration test `RunAsync_AlwaysFailing_MovesMessageToDeadLetterQueue`; 9 tests pass against the test PostgreSQL (3 runs).
