## Keycloak realm roles grant application rights (403 for grace in the example)

- Cause: Keycloak puts realm roles in the nested `realm_access.roles` claim, but `RoleRightClaimsTransformation` only read flat claims (`role`, `roles`, the .NET role type) and the example realm has no mapper that flattens them, so every signed-in user, `grace` included, got no application rights and every `[ApplicationRight]` endpoint answered 403.
- Fix: new option `RoleObjectClaimTypes` (default `realm_access`); the transformation reads the `roles` array of those JSON claims (malformed JSON grants nothing). Documented in `CONFIGURATION_SETTINGS.md`, the ApplicationRights design and `dev-users.md`.
- Tests: 2 new Unit tests in `RoleRightTests` (12 pass). Not run against a live Keycloak: sign in as `grace` again after rebuilding the API to confirm. Only the `admin` role maps to rights in the example, so `ada`, `alan` and `margaret` still get 403 on the guarded endpoints.
