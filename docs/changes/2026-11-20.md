# Changes 2026-11-20

Work finished on 2026-11-20, one section per task. Index: [README](README.md).

## Network discovery moved to OoBDev.System.Net.Discovery

Owner Q25 and the migration plan: the probes (`NetworkDiscovery`, mDNS, SSDP, USR bridge, UDP seam, DNS message) moved with `git mv` from `OoBDev.DevTerm.Core` to the new Framework library [OoBDev.System.Net.Discovery](../../src/Framework/OoBDev.System.Net.Discovery/README.System.Net.Discovery.md); the 9 tests moved to `OoBDev.System.Net.Discovery.Tests` and pass. DevTerm Core, Tui and Web build against the new namespace; DevTerm Core Unit tests: 1104 passed, 1 failed (`CommittedSchemas_MatchWhatTheModelGenerates`: the committed `device-manifest.schema.json` is stale, which also fails without this change; logged in the backlog). Not done: the `LxiDiscovery` probe adapter.

## Desktop OAuth client library (Q2, first slice)

`OoBDev.Security.OAuthClient.Abstractions` and `OoBDev.Security.OAuthClient` with a test project: PKCE S256 (RFC 7636 vector), discovery, loopback receiver that ignores wrong state and other paths, device code polling with `slow_down`, refresh keeping the old refresh token, revocation on sign-out, `TokenCache` with one shared refresh, `BearerTokenHandler` retry after 401, `FileSecretStore`. 16 Unit tests pass. ## DevTerm schemas refreshed, LxiProbe adapter

The committed `schemas/devterm/*.schema.json` were stale; rewritten with `SchemaGenerator.WriteTo`, and `CommittedSchemas_MatchWhatTheModelGenerates` passes. `LxiProbe` (`OoBDev.System.IO.Tcp`, `INetworkDeviceProbe`, name `lxi`) wraps `LxiDiscovery.ScanAsync`: a raw-SCPI device becomes a `tcp` hit, a VXI-11-only one a `vxi11` hit; 1 Unit test. Not done: passing it into the Connection Editor's detect list (stays in BACKLOG).

## OAuth client: Keycloak Integration test for browser sign-in and refresh

New realm client `integration-test-desktop-client` (public, PKCE S256, redirect `http://127.0.0.1:*`). `KeycloakSignInTests` (`Integration`, `oobd-test-keycloak`) drives the real login form over HTTP, so `SignInWithBrowserAsync` receives the code on its loopback listener, exchanges it and `RefreshAsync` renews it; the cookies are replayed by hand because Keycloak marks them Secure. Scope `openid` only: `offline_access` is refused for this client ("Offline tokens not allowed"). Ran against the container: 17 passed. Not done: device-flow test (needs the device grant enabled on a client).

`NetworkDiscovery.DefaultProbes()` (new) lets a caller add probes; `LxiDeviceScanner.CreateDiscovery()` adds `LxiProbe`, and the Connection Editor's "Detect network devices", the Tui `--listnetworkdevices` and the Web `/api/discover` use it. DevTerm.Core unit tests (1105) and the discovery tests pass; the Tui and Web projects build. Not run against a real LXI instrument.

## Example app: right audit trail screen

`/operations/right-audit` (screen spec in `docs/design/example-ui/screens.md`, Figure 9) lists the durable right checks with subject and result filters. The example API wires `TryAddEntityFrameworkRightAudit` with SQL Server, `AddRightAuditLog`, `EnsureCreated` and `MapRightAuditQuery(["audit.read"])` only when `OoBDev:RightAudit:ConnectionString` is set (`audit.read` added to `admin`); without it the endpoint is absent and the page shows "not configured". `OoBDev.Common` now skips `Extensions` `*.Windows.csproj` (the OAuth client Windows project broke the web API restore). 118 Vitest tests pass (5 new), the API builds. Not done: a run against a live SQL Server, a captured screenshot and e2e journey.

## Example app: more Overview probes

The Dashboard now probes the vector store collections, runtime and configuration and endpoint rights APIs besides the five it had (eight in all); `Overview.test.ts` is new (120 Vitest tests pass). Per-provider tiles stay planned.

## OAuth client: device flow sends PKCE, Keycloak test for the device flow

`SignInWithDeviceCodeAsync` now sends a PKCE challenge on the device authorization request and the verifier on the token request (Keycloak refuses the device flow for a client that requires PKCE: `Missing parameter: code_challenge_method`). The test client `integration-test-desktop-client` has the device grant enabled; `KeycloakSignInTests.SignInWithDeviceCode_UserApprovesCode_ReturnsTokens` approves the code by posting the login form of the verification page (redirects and cookies by hand). Both Keycloak Integration tests pass (2 of 2) and 16 Unit tests pass. The realm volume must be removed to import the changed client.

## List control renderers for WPF, Avalonia and WinForms

The `List` control kind now renders in the three desktop form views as a list box bound to `ListViewModel.Items` and `SelectedItem` (WPF data template, Avalonia `ListBox` binding, WinForms `ListBox` kept in step through `Follow`). A Unit test in each renderer's test project selects an item and checks the model (filtered runs pass). Add and delete are the sibling button controls the list names, rendered already. Not built: the Blazor renderer and the Connection Editor profile list.
