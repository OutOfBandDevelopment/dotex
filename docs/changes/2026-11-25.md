# Changes 2026-11-25

Work finished on 2026-11-25, one section per task. Index: [README](README.md).

## EF migration projects retired (desired-state phase E)

`OoBDev.Data.Migrations.Postgres` and `.Sqlite` and the event store `Migrations/` folders and design-time factories are removed (owner, Q37 A; [plan](../design/DesiredStateDatabase/plan.md)). `OoBDev.Data.Migrations.Tests` became `OoBDev.Data.Schema.Tests`, keeping the script-equals-model and sqldef round-trip tests and losing the migration-applies tests. `TryAddPostgresEventSourcing` and `TryAddSqliteEventSourcing` no longer set a migrations assembly. The event store reaches its schema through `EfDesiredStateDeployer.EnsureAsync` (new `DesiredStateStoreTests` on SQLite, and the PostgreSQL Integration fixture), and the readmes say so.

Verified: `OoBDev.Data.Schema.Tests` 12 Unit and Simulate tests pass; `OoBDev.EventSourcing.EntityFrameworkCore.Tests` 19 pass. Not run: the PostgreSQL Integration tests (stack not started) and a full solution build, which fails with NU1605 package downgrades in the DevTerm projects that this change does not touch.

`DatabaseTarget` gained `Schema`, `TablePrefix` and `ForInstance`; `SqldefProvider` scopes each plan with `target_schema` or `target_tables`, so one instance never plans drops for another. `SuppressionsDbContext` takes an instance (`UseSuppressionsInstance`) with a per-instance model cache key. Details: [instances design](../design/DesiredStateDatabase/instances.md#built-2026-11-25). Open: Q42 (where the shared helper lives), `mssqldef` scoping, per-instance history table.

## sqldef is fetched on first use (Q39 C)

Mechanism chosen: download on first use with a pinned hash (a tool restore has no sqldef package; a container adds a runtime the callers do not have). `SqldefInstaller` fetches the pinned release 3.11.30 for the current platform (Windows, Linux, macOS; amd64 and arm64), refuses an archive whose SHA-256 differs from the pinned table, extracts the one executable and caches it per user. `SqldefDownloadingToolRunner` decorates the tool runner, and `AddSqldefDownload()` opts in (a tool on `PATH` still wins). Hashes were computed from the downloaded release assets, not copied from the release page.

Verified: 5 tests in `SqldefInstallerTests` pass (cache once, wrong hash extracts nothing, unpinned tool, platform, and a `DevLocal` run that downloaded the real `sqlite3def` and ran `--version`). Not run: Linux and macOS extraction (tar path untested here).

## Example Overview: provider health tiles (Q40 A)

`GET api/Operations/health` (right `operations.read`) runs the registered ASP.NET health checks through `HealthCheckService` and returns the combined status plus one entry per check (name, status, description, duration), sorted by name. The Overview page lists the providers beside the endpoint probes; a 401 or 403 shows the right that is needed, an empty list says no provider is configured, and an unreachable endpoint says so. The e2e mock answers the new path. The REST API guide was regenerated.

Verified: 2 new Unit tests in `OoBDev.Example.WebApi.Tests` (11 pass), 3 new vitest cases (149 pass in the Example web project), `vue-tsc` clean, `ExampleApiGuideTests` regenerated `rest.md`. Not run: the Playwright journeys, so the Overview user-guide screenshot does not yet show the providers table (no journey step asserts it).

## Desired state: per-instance history table

`AdoAppliedScriptStore` now qualifies `__desired_state_history` with the target's `Schema` and `TablePrefix` (`SchemaScriptFor(target)` gives the matching package script; `SchemaScript` stays the unscoped one), so two store instances in one database keep separate applied-script records. The schema must exist before the first record (the ensure step creates it).

Verified: new `AppliedScriptStoreInstanceTests` (two prefixes in one SQLite file, separate histories, script naming) and the `SchemaPackage` tests pass (7). Not run: the PostgreSQL and SQL Server Integration variants.
