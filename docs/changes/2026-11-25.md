## sqldef is fetched on first use (Q39 C)

Mechanism chosen: download on first use with a pinned hash (a tool restore has no sqldef package; a container adds a runtime the callers do not have). `SqldefInstaller` fetches the pinned release 3.11.30 for the current platform (Windows, Linux, macOS; amd64 and arm64), refuses an archive whose SHA-256 differs from the pinned table, extracts the one executable and caches it per user. `SqldefDownloadingToolRunner` decorates the tool runner, and `AddSqldefDownload()` opts in (a tool on `PATH` still wins). Hashes were computed from the downloaded release assets, not copied from the release page.

Verified: 5 tests in `SqldefInstallerTests` pass (cache once, wrong hash extracts nothing, unpinned tool, platform, and a `DevLocal` run that downloaded the real `sqlite3def` and ran `--version`). Not run: Linux and macOS extraction (tar path untested here).

## Remote DevTerm slice 1: shared key exchanged for a session JWT

The DevTerm web host has `POST /api/token`: the shared key (or the read-only key) as Bearer returns a 15-minute HS256 JWT (`SessionJwt`), and `AccessTokenMiddleware` accepts it as a Bearer for every route, keeping the read-only flag as a claim. A session JWT cannot mint another. The design and the remaining slices are in [Remote DevTerm](../design/RemoteDevTerm/README.md). The API guide was regenerated. `Microsoft.Extensions.Options` in `Directory.Packages.props` moved to 10.0.14 to clear the NU1605 downgrade that stopped the DevTerm projects from restoring.

Verified: 4 new tests in `SessionJwtTests` (validity and read-only claim, expiry on a fake clock, foreign and garbage tokens, the endpoint over a live host) and the existing `WebRoles` and `AccessPolicy` tests pass (23 in total).

## Remote DevTerm slice 2: device byte tunnel and remote adapter

The host serves `/ws/device/{name}`: it opens the device adapter of a saved connection and relays raw bytes both ways over binary WebSocket frames (403 for a read-only token, 404 unknown name, 502 device will not open). `RemoteDeviceAdapter` (a `StreamDeviceAdapter` over a `WebSocketStream`) exchanges the shared key at `POST /api/token`, then connects the tunnel with the session token. The AsyncAPI document and the streaming guide list the new channel. Tests: 4 Unit tests on a live host with a loopback connection (round trip of `hello`, wrong key, read-only key, unknown connection). Not done: Tui and WPF connection type (slice 4), HID and USBTMC boundary framing, raw bridge removal (slice 5); Q43 still open, default A taken.

## Remote DevTerm slice 4: remote connection type in the shared options

Transport `remote` joins `CliOptions` (`--host` the web host address, `--remoteconnection` the saved connection, `--password` the host key), the validator, the connection description and error hint, the profile writer (the key is never saved), the editor transport list and `AddDevTermFrontEnd` (`RemoteDeviceAdapter`). Tui and WPF take it from the one generated form (new "Remote" section), and `schemas/devterm/connection-profile.schema.json` gained `RemoteConnection`. Every connect exchanges the key for a fresh session token, so no refresh logic is needed. Tests: 4 validator cases, 2 wiring tests, the form-section and schema drift tests updated; Core.Tests 1133 passed, 5 skipped. Not done: key from the credential store, a live Tui or WPF run against a host.

## Cold-stack Integration start: ordered waves script (default of Q45)

`scripts/ci/start-integration-waves.ps1` starts the Docker stack in four waves with `docker compose up -d --wait` each (heavy services first), then the one-shot `moto-init`, skipping names the compose file does not define; `-DryRun` prints the commands. Verified with `-DryRun` and a real start (the first run failed in wave 4 because `moto-init` exits after its job and `--wait` counts that as a failure, so one-shot services now start after the waves without `--wait`; the second run succeeded in 5 s with the stack already up); a full cold whole-solution Integration run was not repeated, so the issue stays open and Q45 asks which approach the owner wants.
