## Plugin sandbox: caller death, signed packages, grant broker, Linux

- Caller death: `SharedInstanceLock` (cross-process named mutex, abandoned-owner detection), `ReconnectRegistry` (token rules, logic only) and tests that kill a real caller process and see the plugin die (kill-on-close) or live on (Survive). Finding: a named mutex lives only while a handle is open, and abandonment is signalled only to a waiter.
- Signed packages (REQ-006): `PackageSigner`, `PackageVerifier`, `TrustList` (ECDSA P-256 over the manifest bytes, SHA-256 per file; missing, unknown key, bad signature, modified, missing and unlisted files and path escapes are refused).
- Grants and broker (REQ-002, 003, 004, 007): `GrantStore` (approved subset only, who and when, audit trail, revoke) and `GrantBroker` (folder and read-only checks, exact host and port, redirects re-checked, refused calls never reach the network). 25 Unit tests.
- Linux (REQ-008): `BubblewrapPlugin` and 6 Integration tests run in the dotnet sdk container with bubblewrap (`scripts/spikes/run-sandbox-linux.sh`): network, files, environment and PID isolation pass with positive controls. They end Inconclusive on Windows. Not built: Linux process-count limit (needs cgroup delegation); a Survive transport (named pipe).
- Cross-platform: `ISandboxedPlugin` implemented by `SandboxedPlugin` (Windows), `BubblewrapPlugin` (Linux), `SeatbeltPlugin` (macOS, unrun) and `PlainPlugin` (unsandboxed control); `SandboxLauncher` picks one. `CrossPlatformEscapeTests` run the network, file and environment attempts on whichever exists. Windows-only tests now end Inconclusive elsewhere. Windows 97 passed, 6 skipped; Linux container 86 passed, 17 skipped (Windows-only). Fixed a race creating the AppContainer profile when tests run in parallel.
- Host chain: `PluginHost` verifies the signed package, requires the owner grant (and that it does not exceed the manifest), takes the cross-process mutex for Shared (`InstanceHold`, a dedicated owner thread because a mutex is thread-bound), launches in the platform sandbox and leases from the pool. `BrokeredPlugin` answers `broker.file.read`, `broker.file.write` and `broker.fetch` requests only when both the grant and the request context rights (`files.read`, `files.write`, `net.fetch`) allow them; the plugin receives the context (declared claims only) in a `context.set` frame. 8 Integration tests (`PluginHostTests`) pass on Windows and in the Linux container. Limit: a second process asking for a held Shared plugin is refused (`InUseElsewhere`); sharing across processes needs the Survive transport.
- Linux limits: `BubblewrapPlugin` takes `JobLimits`: memory via `DOTNET_GCHeapHardLimit`, CPU time via `ulimit -t`, wall time via a kill timer; 3 Integration tests (`LinuxLimitTests`) pass in the container. Memory is a managed-heap limit, not a hard OS cap.

## SerialDeviceAdapter reopen leak fixed, BridgeWorker reviewed

`SerialDeviceAdapter.OpenAsync` after a device-side close or unplug created a second port without releasing the first (the state was Closed but the port and pump remained). It now closes the previous one first; one new unit test. `BridgeWorker` was read in full and no defects were found.

## Broker, Mqtt and BLE adapter reconnect leak fixed

`BrokerDeviceAdapter.OpenAsync` and `MqttDeviceAdapter.OpenAsync` after a broker-side disconnect never disposed the old connection, so its socket stayed open and its late `MessageReceived`/`Disconnected` events completed the new pipe and faulted the new state. It now closes the old connection first and ignores an open call while already open or opening; one new unit test each. `BleDeviceAdapter.OpenAsync` had the same defect after a peripheral-side disconnect (old connection never released, late notifications reached the new pipe) and got the same fix.

## Markdown PlantUML renderer: source escaped in the HTML details block

`PlantUmlRenderer.Write(HtmlRenderer, ...)` wrote the diagram source unescaped into `<pre><code>`, so markup in a diagram (for example a `<script>` in a note) reached the page as live HTML. It now uses `WriteEscape`. A second constructor accepts an `IPlantUmlRenderer`, which gives the project its first Unit tests (the only existing test is DevLocal). The hard-coded public `plantuml.com` back end is recorded as an open finding.

## YAML and JSON navigators: keys that are not XML names, multi-document YAML
