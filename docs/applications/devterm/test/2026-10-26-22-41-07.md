# Z-Stick S2 node 2 read-only pass (raw serial)

Routine confirm of the Z-Wave Serial API against the real Aeotec Z-Stick S2 on COM13 (115200 8N1) and node 2, a GE 45603 plug-in appliance module. Raw serial from a PowerShell script, not the dev-term panel, because the panel could not be driven unattended. Nothing was switched.

## Device matrix

| Device | Transport | Result |
|---|---|---|
| Aeotec Z-Stick S2 (home ID 016A1C28) | serial COM13, 115200 8N1, DTR/RTS on | confirmed working |
| Node 2, GE 45603 Plug-in Appliance Module | Z-Wave via the stick | answers Manufacturer Specific and Binary Switch Get |

## Commands

Each is a SendData request (function 0x13, node 2, transmit options 0x25, callback id 0x7B) with the command-class bytes below. The script (`/tmp/z.ps1`, kept out of the repo) sent an ACK first, wrote the frame, and read for 4 s.

| Sent (command class bytes) | Raw reply (decoded part) | Meaning |
|---|---|---|
| `72 04` Manufacturer Specific Get | `01 0E 00 04 00 02 08 72 05 00 63 52 50 30 30 E9` | manufacturer 0063, type 5250, id 3030 = GE 45603 |
| `86 11` Version Get | reply arrived late, mixed with the next read | not captured cleanly |
| `25 02` Binary Switch Get | `01 09 00 04 00 02 03 25 03 FF 2A` | switch report: **on** (FF) |
| `70 05 01` Configuration Get, parameter 1 | no Configuration report; only the switch report again | expected: this product has no configuration parameters |

## Findings

- Replies lag one command behind: the stick retransmits an unACKed frame, and this crude script ACKed once per read window. The dev-term panel's `ZWaveAckResponder` ACKs every frame, so this is a limit of the script, not of the plugin.
- Version Get was not captured; repeat it from the panel's Describe node.
- Node 2's outlet is currently on.

## Summary

No dev-term change. Still to run from the panel: Describe node end to end, Configuration set, and switching the outlet on and off.
