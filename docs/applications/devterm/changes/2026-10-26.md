# 2026-10-26

## Z-Wave plugin for the Aeotec Z-Stick S2

New device plugin `DevTerm.Devices.ZWave` (`plugins/zwave`, presenter `zwave`, panel `zwave`, serial only). Pieces: `ZWaveFramer` (SOF/length/type/function/payload/checksum framing across reads, plus ACK/NAK/CAN), `ZWaveInterpreter` and `ZWaveNames` (readable text and indicator values for GetVersion, MemoryGetId, capabilities, controller capabilities, init data with node ranges, SUC id, node protocol info, SendData callbacks, ApplicationCommandHandler), `ZWaveDecoder` (presenter, structured values, typed hex input: `function [payload]` or a full `01 ...` frame, always led by an ACK), `ZWaveControlSurface` and `ZWaveUiDefinition` (Refresh, Node info, Basic Get; read-only) and `ZWaveAckResponder`, which ACKs each frame the stick sends while the panel is open (off the read loop, queued, because an unACKed callback is retransmitted and the next request gets CAN).

Tests: 25 unit tests (`ZWaveDecoderTests` on frames captured from the real stick, `ZWaveControlSurfaceTests`) and `RealHardwareZStickTests` (opt-in, `RealSerialZStickS2Port`/`ExpectedHomeId` in `devterm.runsettings`). The bundled-presenter lists in `DevTermSessionBuilderTests`, `ConfigureModeTests` and `DeviceProfilesWindowTests` gained `zwave`.

Verified on a real Z-Stick S2 on COM13 (Z-Wave 2.78, home ID `016A1C28`, 26 nodes): [docs/test/2026-10-26-15-43-09.md](../test/2026-10-26-15-43-09.md). Nothing was switched. Docs: [spec](../specs/zwave-panel.md), [user guide](../user-guide/zwave-controller.md), [device notes](../devices/aeotec-zstick-s2/known-configuration.md), [proposal](../design/proposals/z-wave-support.md).

Pre-existing, not from this change: `AttachCliModeTests` lacks a `[TestCategory]` (fails `EveryTestClass_DeclaresARecognizedTestCategory`), and `PluginTrustTests.TheLazyPresenter_...` needs python.

## Z-Wave panel: no-reply message and screenshots

Reported: clicking Refresh on COM13 showed nothing. Cause (reproduced with the CLI): the connection was at the 9600 baud default, and the stick only answers at 115200. Refresh now throws a `TimeoutException` naming the baud rate when the stick is silent for 2.5 s (`ZWaveAckResponder.BytesReceived`; test `Refresh_WithNoReply_ExplainsTheBaudRate`). The user guide gained a "Set the baud rate" section and the panel screenshots `tui-control-panel-zwave` / `wpf-control-panel-zwave` (new tests in both `ControlPanelScreenshotTests`, using frames captured from the real stick); the spec documents the no-reply handling.

## Z-Wave: control, enumerate, network management and events

`ZWaveCommands` builds the requests (Binary Switch Set/Get, raw SendData, AddNode/RemoveNode, SetDefault, SetLearnMode, NeighborUpdate, Is/RemoveFailedNode, RequestNodeInfo, SoftReset). The interpreter decodes their callbacks (include/exclude progress, reset, neighbor update, ApplicationUpdate node info, more command-class reports). `ZWaveDecoder` keeps a per-node table (replies that carry no node id are attributed through `Expect`, in request order) and publishes `nodeTable` and `lastEvent`. The panel gains Enumerate, Control a node and Network management sections; erasing actions use `ConfirmMessage`. `ZWaveAckResponder` raises `FrameReceived` so Enumerate can read the node list.

Tests: byte-exact request and callback tests (`ZWaveCommandsTests`), surface frame tests, node-table attribution; 42 pass, 1 skipped. A real-hardware Enumerate test exists but was not run (COM13 was held by another process). **None of the new commands was run against the stick**; the network-management bytes are from memory and need a bench check.

## Z-Wave: Describe node (discovery queries)

The Z-Wave panel's "Query a node" section has a **Describe node** button (`describeNode`). It asks the chosen node for its node information frame, then sends each discovery query the node's command classes allow: Version Command Class Get for every supported class, Z-Wave Plus Info, Association Groupings, Multi Channel End Point and Security Commands Supported. The decoder now describes the matching reports. Unit-tested only; not yet run against a real node (the Z-Stick has no paired devices at the moment). A node profile format keyed on manufacturer id, product type and product id is still to come.

## Z-Wave: ported id tables and manufacturer configuration parameters

The plugin embeds factual identifier data under `src/DevTerm.Devices.ZWave/Data/`: 605 manufacturers and 1,334 products (`manufacturers.json`, from OpenZWave's `manufacturer_specific.xml`), 69 command classes and 52 device classes (from PyZwaver's `zwave.py`), and the manufacturers' configuration parameters (command class 0x70: index, label, size, range, default, help, list items) for 830 product files, with a `products` map keyed `mmmm:tttt:iiii` (`product-configs.json`, from OpenZWave's `config/`). `ZWaveRegistry` loads them lazily; `ZWaveNames` falls back to them, so a Manufacturer Specific report now names the manufacturer and product and says how many parameters are known. The protocol is standard, so those parameter lists are what varies per product.

New panel actions **Configuration get** and **Configuration set** (`70 05 p`, `70 04 p size value`) take `parameter` or `parameter value [size]`; the interpreter decodes Configuration Reports (`70 06`). Tests: `ZWaveRegistryTests` (58 unit tests pass). Unit-tested only; no node is paired to the stick yet.

**Licensing:** OpenZWave and PyZwaver are GPLv3. Only identifier-to-name data was taken (ids and parameter descriptions as facts about devices); no code from either project was copied. Re-check this if the data is ever redistributed outside the repository.

## Z-Wave: aligned node table and a manufacturer-parameters list

- The panel's "Nodes" indicator is now one aligned row per node (Node, Device, Product, Version, Classes) instead of a long `;`-joined sentence. The product column names the manufacturer and product from the registry (e.g. `GE (Jasco Products) 45603 Plugin Appliance Module` for the outlet relay on node 2); the class column shows a count, and the last report stays in the "Last report" indicator.
- New "Manufacturer parameters" section: when a node's Manufacturer Specific report arrives (Describe node), the decoder publishes `nodeParams`, one line per known configuration parameter (number, label, size, range, default, named values) or a note that the product has none. The GE 45603 has none, which is correct for a plain relay.
- Tests: ZWaveDecoderTests (parameter list for node 2's real ids, for an Aeotec product with parameters, aligned table). Not yet re-captured in screenshots or added to the user guide/spec.

### Z-Wave docs brought current, and a docs merge gate
